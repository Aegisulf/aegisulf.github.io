Changelog

What changed in each version. The newest is on top.

0.9.7 (2026-10-23)

  • Two copies on one PC (for example the Microsoft Store version and a portable one): each copy now runs on its own. Before, starting one while the other was running handed the start to the other copy, which opened its own window with its own settings.
  • The welcome window: the Microsoft Store does not start a program after it is installed, so the first start is often a double-click on an archive. That first window now offers the welcome window in a one-line notice above the list ("Set up" or "No, thanks"); the compact windows of the context menu and the previews are not interrupted.
  • Microsoft Store version: the last step of the welcome window keeps the context-menu switch changeable (the Windows 11 menu and the file types stay built in).
  • A new app icon: a zipper being pulled open across the top of the moon, so the icon says what LycanZip does (the small sizes keep the plain wolf).

0.9.6 (2026-10-23)

  • Microsoft Store version on Windows 10: the right-click menu could be missing (0.9.5 hid the command of the package in the classic menu, which is the only menu of Windows 10). It is shown again, with its sub menus.
  • Microsoft Store version: "Add LycanZip to the context menu" is a real switch now. The menu is part of the package and stays registered, but when the switch is off LycanZip shows no entries in File Explorer. The cards that register file types, the Windows 11 menu or restart File Explorer are not shown (there is nothing to register), and the note at the top explains how the menu and the file types work in this version.
  • Microsoft Store version: "Open default apps settings" could not be clicked. It works and opens the settings of the package.
  • The README has screenshots, the ways to get LycanZip and a note on compatibility before 1.0.

0.9.5 (2026-10-23)

  • Microsoft Store version: on newer builds of Windows 11, "Show more options" showed LycanZip twice. The command of the new menu now hides itself there, and the classic menu (with its sub menus) is the one entry.
  • Two copies on one PC: when the Microsoft Store version is installed, it provides the right-click menu and the file types. The installer, zip and portable versions switch their own off when they start, so File Explorer shows LycanZip once, and they say so one time, with a button that opens Installed apps. Their switches on the Explorer tab and in the welcome window are off. The Store version names another copy that still has a menu registered.
  • Microsoft Store version: the settings, presets, logs and crash reports are kept in the package's own folder. The first time, the settings and presets the Store version used so far are copied there. Before, Windows redirected them, so the Store version could read the settings of another copy until it saved once, and "Open the settings folder" showed files it did not use.
  • The prompt "the menus point to another copy" (a moved portable folder, or an installed copy next to a portable one) now says where they point now; its button is "Use this copy".

0.9.4 (2026-10-22)

  • Microsoft Store version: in the new Windows 11 right-click menu, "Compress with a template", "Other formats" and "Extract to a recent folder" opened empty (Windows shows no sub menu inside the LycanZip menu). Their entries are now listed in place, between two lines, for example "Compress with a template: Backup". The classic menu keeps its sub menus.
  • Microsoft Store version: the package has a resource index, so Windows uses the large, unplated icons in Start, the taskbar and "Open with" instead of a small plated one.

0.9.3 (2026-10-22)

  • Microsoft Store version: the new Windows 11 right-click menu of an archive no longer shows "LycanZip > LycanZip > entries". It is one command for every kind of selection now, and Windows no longer wraps it in a menu of its own.
  • Microsoft Store version: the classic menu ("Show more options") has the LycanZip entries for every file and folder (it had them only for archives), and the right-button drag menu ("Extract here / Compress here") is there.
  • Microsoft Store version: the settings show the right-click menu and the file types as built in instead of "not supported", the switch of the classic menu is not offered (it cannot work from a package), and the check for new versions is not shown (the Store updates the program).
  • The icons of the package (Start, "Open with", the file types in File Explorer) are made from the current logo in every size Windows asks for; they were blurry and had an old design.

0.9.2 (2026-10-21)

  • Four more columns for the details view (off by default; tick them in the menu of the column headers): ratio, encrypted (a lock), method and CRC. Every one sorts. The Properties window of an item has a technical part: created / accessed time, method, Unix permissions, the system that made the entry, flags, link target, the solid block, where the item starts in the archive, and the comment.
  • The details view scrolls sideways when its columns are wider than the window (no column is hidden any more), the header follows. The width of a column can be dragged at the right edge of its header (a double click restores it, and "Reset column widths" is in the menu of the header); the widths are remembered.
  • "Look up on VirusTotal" (in More options, in the menu of a file in an archive, and next to a SHA-256 value in the hash values window): the SHA-256 is calculated (a file in an archive without unpacking it to disk) and the VirusTotal page of that hash opens in your browser. Only the hash is in the address; nothing is uploaded and there is no API.
  • The bundled 7-Zip engine (7z.dll) is now 7-Zip 26.04, which fixes security issues in the format readers.
  • Icons in menus and on task cards carry a colour for what the action does: delete is red, malware scan and VirusTotal are amber, test and verify are green, add / rename / edit use the accent colour of the theme. Everything else keeps the colour of the text.
  • The last step of the welcome window offers "Check for new versions" (off unless you switch it on; not shown in the Microsoft Store version, which the Store updates).
  • An installer (per user, no administrator needed) is made besides the zip packages. An installed copy updates itself: after the automatic check the update is downloaded in the background, checked against a signature of ours, and the notice offers "Restart and update" (nothing is installed until you choose; "Install now" does the whole thing by hand). The zip and Store versions are updated as before. The installer shows a splash image while it installs, and the right-click menu DLL of an installed copy is only copied out of the program folder when the menu is switched on.
  • winget installs the installer (winget upgrade and winget uninstall work on it) and no longer lists the Windows App Runtime as a dependency; the Scoop package does not need it either.
  • The About page links to the web site and to the source code on GitHub.
  • Adding a language is one row in src/core/include/lycan/languages.h plus the translation file: the settings page, the welcome window, the right-click menu and the packaging scripts all follow that list.
  • The zip packages and the installer carry the Visual C++ runtime files too: on a Windows 10 that never had the "Visual C++ Redistributable", LycanZip did not start ("VCRUNTIME140.dll was not found"). The right-click menu DLL no longer needs it at all.
  • The zip packages and the installer carry the Windows App Runtime: nothing has to be installed first.
  • LycanZip loads only the 7z.dll it came with: the file next to the program, checked against its SHA-256. A missing or different file gives an error that says to reinstall; another 7-Zip on the computer is never picked up.
  • The tooltip of "Scan for malware" showed its string id; menu items now get their tooltip translated. The Close buttons say "Close" in English.

0.9.1 (not released yet)

  • The Explorer menu DLL has the version in its file name (LycanZipShell-0.9.1.dll), so an update of a zip, winget or Scoop install no longer has to overwrite a DLL that Explorer holds. After an update in the same folder LycanZip points the menu to the new DLL by itself, removes the old DLLs when Explorer lets go of them, and offers to restart Explorer. The Explorer tab of the settings has a "Restart File Explorer" button for the same purpose.
  • A new chibi wolf on the web site and in the strip above an open archive; the start page shows the program icon; the picture of the welcome window follows the accent colour that is chosen.
  • The names of the built-in presets are English keys now (Backup, Smallest size ...); the menus and the compress page still show them in the language of the interface. The old Chinese names are still accepted in the settings and in --template. Separators and brackets in status lines follow the interface language too.
  • Optional check for a new version (About page, off by default): once a week it reads one small file from aegisulf.com; it sends nothing but the program name and version. The Microsoft Store version is not checked (the Store updates it); winget and Scoop installs are told the update command; zip installs get a link to the download page and can skip a version.
  • Files dragged out of a solid archive (7z) are unpacked in one pass and arrive in Explorer while they are made, instead of being unpacked to a temporary folder first.
  • The picture preview can save a picture in another format (PNG, JPEG, BMP, TIFF, GIF, and more when Windows has the codec) and set it as the desktop picture.
  • Version 0.9.0. The program files are described as "LycanZip File Archiver".
  • Hold Shift (or Ctrl, or nothing: a setting) when you open an archive to go straight to the picture preview; an archive without pictures opens as usual.
  • The thumbnail strip of the picture preview can be dragged out: drop a picture in Explorer to copy it.
  • The audio preview shows the format, bit rate, sample rate, channels, length and size of the file where a cover picture would be.
  • Dialogs of the small window of the context menu are drawn straight on the window, and the buttons of the archive view lose their texts when the window is narrow.
  • The file of an archive is locked while its window shows it (a setting): other programs cannot rename or delete it.
  • Picture thumbnails in the icon view have a thin plate under them, the icons of the list and the folder tree have a second tone, and the archive view has stars and a faint wolf at the top.
  • The picture preview says where it is when it goes round ("This is the first picture"), "Open with the associated program" is greyed out where it cannot work, and its menu has icons. After the password of an archive was given the lock icons make way for the icons of the file types.
  • Compression templates remember whether to write the checksum files of the archive and of its files (the built-in "E-mail / share" and "Backup" do); an archive in volumes gets one line per volume.
  • The audio preview has a playback mode: in order, repeat all, repeat one track, shuffle (also the key L).
  • New accent colour "Night" (a near-black background and a silver accent).
  • The Home button moved next to Up, "Extract to…" has a drop-down with the folders that were used before and the Desktop, Documents and Downloads, the context menu has "Paste" for files that were copied in Explorer, and the title of the window shows the percentage while something is being done.
  • A found threat is now explained: the antivirus may list lycanzip-cli.exe as the "affected item"; that is the program that handed the content over.
  • New: "Calculate and save as name.sha256" in the right-click menu of files, folders and archives (both menus, switched on by default; it can be switched off in Settings > Explorer). One item gives <item name>.sha256 next to it, several give <name of their folder>.sha256 in that folder. Nothing is shown when it is quick: a notification says it is saved. A window comes only when it takes long (progress, a way to cancel), when the file is there already (replace it, keep both, cancel) or when something went wrong.
  • The one-line notices above the list (the filename encoding, a checksum file next to the archive) take a third of the height they did.
  • A window that is started for a right-click action or an archive no longer shows the home page for a moment first: it appears when it has the screen that fits (the small window, the loading view). The hash values and verify windows are the small window too.
  • New: checksum files. Verify .sha256, .sha1, .sha384, .sha512, .md5 and .sfv files (and SHA256SUMS style names): "Verify the checksum file" in the right-click menu of those files (several at once go into one window), LycanZip.exe x.sha256, lycanzip-cli verify, and "Verify a checksum file…" in the menu of an open archive, which checks the files inside the archive without extracting them. Only what is wrong is listed; when everything matches it says so. Names that don't meet (a checksum file made one folder higher or lower than the archive) are matched by themselves, and asked about only when that fails.
  • New: an archive that has a checksum file next to it (name.zip.sha256, or name.sha256 for the files inside) shows a bar above the list; one click checks it. The hash values window of a file also compares with the checksum file next to it.
  • New: hash values of folders (every file in them, in all levels) from the right-click menu, saved as <folder>.sha256 beside the folder.
  • New: settings (and the compress page) to write a checksum file with every new archive: name.zip.sha256 for the archive itself and name.sha256 for the files that went in, with the names they have in the archive. Both are off by default; lycanzip-cli a takes --sums-archive and --sums-files.
  • New: the menu of a right-button drag. Drag files with the right mouse button onto a folder, a drive or the desktop and the menu that opens has a LycanZip entry: compress the dragged files into that folder, or extract the dragged archives there. It follows the same settings as the right-click menu and is registered with it (the classic registration, so it needs no package on Windows 11).
  • Fixed: the sound set chosen in Settings could not be changed (it always went back to Synth).
  • Fixed: pictures rotated by 90 or 270 degrees were squeezed and shown wrongly in the preview.
  • Fixed: creating a BZip2-compressed archive (.tar.bz2, or BZip2 as the method of a zip or 7z) on a disk that ran full never ended: the multi-threaded BZip2 encoder of 7z.dll waits forever when its output fails. The error is reported now and nothing is left behind.
  • Extracting an archive that would unpack to far more than it is (1 GB or more and over 500 times its size, or 1 TB or more: a compression bomb or a disk image) now asks before anything is written. Settings > Extract can switch the check off.
  • Icon view: the icon size (small, medium, large and a new huge one) now sizes every cell: pictures show thumbnails and other files get icons as big, instead of a small icon in a big cell. The right-click menus of the list and the folder tree have icons on the important items (delete in red).
  • A right-click action (compress, extract, test, add, hash) now always opens its own compact window, also when LycanZip windows are open already: its progress no longer shows up in the window of an archive you are looking at.
  • New: a welcome window at the first start (three steps: look and sound, view and previews, Windows integration). Nothing is registered with Windows before "Finish". New settings: double-clicking an audio file can open the built-in player; new users start with the icon view and medium thumbnails.
  • New theme choice "High contrast (black)" in Settings: white on black with bright accents, independent of the Windows setting. A Windows contrast theme is followed too: the colours the program sets itself use the system text colour there.
  • Comic book archives (.cbz, .cbr, .cb7, .cbt) have an icon of their own and are offered in "Open with" / Default apps (LycanZip does not take them over from the comic reader you use).
  • New: create ISO images (ISO 9660 with Joliet: long names, any language; files must be smaller than 4 GB) from the compress page and lycanzip-cli a x.iso <inputs> [--iso-label NAME] [--iso-now].
  • Adding files to an archive that has items of the same name now offers update modes: replace and add (default), update and add (only files that are newer on disk replace), update existing only. lycanzip-cli u --add takes --mode replace|update|freshen|sync (sync makes the archive match the folder and asks before deleting in the app) and --dry-run to preview.
  • Making an archive whose file already exists asks whether to save under a new name, replace it, or add to it with an update mode, instead of silently appending (2).

0.8.2 (not released yet)

First version. Highlights:

  • Open, browse, preview, test and extract archives; create archives (zip, 7z, tar.gz, tar.xz, tar.bz2) with presets, encryption and split volumes. 7-Zip engine (7z.dll), WinUI 3 interface, command-line tool, portable / MSIX packages.
  • Explorer context menu (classic and Windows 11 style): names follow the selection, entries are chosen in Settings, image and audio preview straight from the menu.
  • Archives made on a Mac: the __MACOSX folder, ._ files and .DS_Store are hidden, never previewed and skipped when extracting (each can be switched off); Thumbs.db is left out of added folders.
  • Smart store: photos, music, video, archives and other files that are compressed already (64 KB and up) are stored as they are when making a zip or 7z instead of being packed again (known by their extension, otherwise by looking at samples of their content) (faster, same size; a switch on the compress page and in presets, off in the "smallest" preset). A 7z of mostly such files is no longer solid, so each file can be read on its own (thumbnails); other 7z files get a 256 MB solid block limit.
  • "Scan for malware" (More options menu, lycanzip-cli scan): every file is handed to the installed antivirus product through AMSI. When Windows Defender is the antivirus, the name of the threat is shown (read from its event log). Needs real-time protection; files over 128 MB are skipped (Defender does not scan them either) and reported as skipped, never as clean. It is not a guarantee.
  • The "Compress with a template" list of the Explorer menu is chosen by the user: each template (built-in or your own) has a switch, on the settings page and in the template menu of the compress page. By default only "smallest", "backup" and "store only" are listed.
  • Settings > About > "Data location" shows whether the settings live in the program folder (portable) or in your user folder, and switches between the two: the settings and templates are copied to the new place (the old files stay), then LycanZip restarts.
  • A diagnostic log (logs\lycanzip.log, 2 MB per file, four files at most; in the portable folder or in %LOCALAPPDATA%\LycanZip): errors and warnings are always written, the detailed messages (what was opened, how long tasks took) when "Detailed debug log" is switched on in Settings > About. File names only unless "Log full paths" is on; never passwords or file contents. "Copy diagnostic information" puts the version, Windows, the engine and the last lines of the log on the clipboard for a bug report.
  • Hash values: "Calculate hash values…" in the Explorer menu (files and archives), in the menu of items in an archive and in "More options": CRC-32, MD5, SHA-1, SHA-256, SHA-384 and SHA-512 at once; paste a value to compare it; copy all; save as a .sha256 checksum file. lycanzip-cli hash (also --in <archive> and --check <checksum file>) writes and reads the format of sha256sum.
  • "Archive information…" (More options, Alt+Enter with nothing selected): format, sizes, ratio, method, solid, encryption, volumes, comment.
  • Ctrl+V pastes files and folders copied in Explorer: into the sources of the new-archive page, or into the archive on screen.
  • Opening a later volume of a split archive (.part2.rar, .r00, .z01, .002 ...) asks, every time, whether to open the first volume instead.
  • Built on Windows App SDK 2.5 (the framework-dependent builds need the Windows App Runtime 2.5, winget install Microsoft.WindowsAppRuntime.2).
  • Edit a file inside an archive: "Edit" extracts it, opens it in Notepad (text), the associated program or an editor of your choice, and offers to put it back when you save. Change an archive in place (zip, 7z, tar): drag files into the window or use the Add button, delete items (Delete), rename (F2), make folders. Unchanged items are copied through without being recompressed; nothing is touched if the change fails or is cancelled; an optional backup (.bak). lycanzip-cli u does the same from the command line.
  • Fixed: Enter in the image preview when a toolbar button has the focus; previews now close when the window shows another archive.
  • Fixed: fonts (.ttf / .otf) opened from an archive; the beep on Alt+P / Alt+Shift+P; the preview strip with same-named pictures in different folders.
  • Dragging files out of an archive into Explorer streams them (virtual files): no waiting with a "no drop" cursor for big files, nothing is unpacked beforehand. A setting switches back to unpacking to a temporary folder first (for programs that only take real files).
  • The folder tree: drag folders (or the archive itself, as a folder named after it) out, right-click menus (the archive's own menu with delete / properties / show in Explorer, shared folder menu), an archive icon on the root.
  • The icon view wastes less room: the cells are as high as the folder needs (the lines of the longest name, at most 2, a picture area of the size of an icon when there are no thumbnails), and the pictures sit on the names.
  • The files and folders of the lists and the folder tree show the icons of Windows (by kind of file, as in File Explorer; Settings > View switches back to LycanZip's own coloured icons).
  • Dragging files out of an archive shows the picture and the "Copy to ..." text next to the cursor (the icon, the name, how many items or how big).
  • Explorer's "Type" column tells the kind of archive: "LycanZip ZIP archive", "LycanZip GZ archive" ... (one program id per extension, in the language of the program).
  • Extracting an archive that is damaged or cut off keeps what could be read of each file (pictures, videos and text are often still usable) instead of deleting it; the finished card lists the files that have an error, and a switch in Settings > Extract (--discard-broken on the command line) goes back to deleting them. A good file is never replaced by a damaged one: the damaged version is kept beside it as "name (damaged).ext". A wrong password, a cancel and a full disk still leave nothing behind, and a file that is overwritten is only replaced when the new content is complete.
  • Zip files whose packed size is a few bytes larger than the compressed data (some servers write them; 7-Zip reports "data after the end of the payload" although the CRC matches, Windows and Bandizip extract them) are extracted now, with a note on the finished card, instead of failing and deleting the files.
  • The compact window of the right-click actions: a "Done" button (or "Close" when something failed; Enter and Esc work too) when everything has finished, a fixed size (it cannot be resized or maximized), and it no longer closes by itself unless "Close the window when done" is ticked.
  • Sound effects: two sets, "Synth" (default) and "Wave" (Settings > Appearance); every sound starts with 100 ms of silence so that an audio device that was idle does not swallow the start.
  • Moving a portable LycanZip folder: when the right-click menus or the file associations still point to the old folder, the program says so when it starts and offers to point them to the current one (or not to remind you again); nothing is registered unless you click.
  • Archives inside an archive show their file-type icon in the list, the details and the icon view.
  • Windows 11: a separate switch in Settings > Explorer adds LycanZip to the top level of the new right-click menu (a per-user sparse package, no administrator rights; it needs the signed menu package that comes with the release). The classic menu switch stays and both can be on.
  • The Explorer menu has icons of its own: the file-type icon for compressing to a format and for opening an archive, a wolf with a coloured badge for extract, test, preview, encrypt, hash values and templates.
  • File-type icons: a wolf on a night-sky document with the extension on a label and the wolf's tail behind it, six families (ZIP, 7Z, RAR, TAR, ISO, other) in different colours. They are used by the file associations (once LycanZip is the default program of a type), the MSIX file types, the breadcrumb and the folder tree.
  • English, Traditional Chinese and Simplified Chinese interface.
